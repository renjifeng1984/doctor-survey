前提：这条线是兜底路线，与小程序线（路线 A）并行，不替代。目标是把"不肯进小程序"的医生捞回来。

1. 定位

一条不打开小程序的调研路线：CC 在企业微信单聊里按脚本逐题提问，医生用文字回答，全程不离开聊天窗口。

医生侧的成本只有"打字"，没有安装、没有登录、没有跳转。

2. 目标与非目标

目标

  • 覆盖不肯进小程序的医生，把整体完成率从当前水平往上拉；
  • 医生侧零门槛：不装、不登、不跳。

非目标（本期不做）

  • 不做机器人自动提问——官方能力不支持（见第 3 节）；
  • 不做答案结构化入库——本期答案只存在于聊天记录里；
  • 不做语音转写、不做图片识别；
  • 不做聊天以外的任何跳转。

3. 能力边界

这条线怎么设计，完全由企微的能力决定：

能力是否可用说明
官方机器人进外部单聊自动对话不支持官方明确：外部 1v1 不提供机器人服务
以员工身份调 API 自动回复客户不支持，属风控红线会被判定异常并限制账号
在外部群加智能机器人不支持仅内部群可用
会话内容存档拉取单聊可用，但需对方同意本期不启用（第 8 节）
第三方 RPA / Hook 外挂官方不支持有封号风险，不采用

结论：问题只能由 CC 手动逐条发。所谓"自动化"只可能发生在企业侧（解析、登记），不发生在对话本身。

4. 谁走这条路

分流顺序：

  1. 先发小程序卡片（路线 A，成本最低）；
  2. 医生出现以下任一反应 → 转聊天版：
  • 明确说"不装/不会用小程序"
  • 说"你直接问吧"
  • 24 小时内三次未打开卡片
  1. 转聊天版后，小程序侧该任务标记为「已转人工」，不再推送、不再计入待办。

一条铁律：同一个人、同一个项目，只能走一条线。两头都做等于让医生答两遍。

5. 开场

首版按 8 题设计，现按 32 题执行，因此开场要分两次话术：首次、续聊。

首次（不超过 3 行）：

王主任您好，我们是做风湿免疫领域调研的。想请您聊聊系统性红斑狼疮的诊疗习惯，题目分三次问，每次十分钟左右，您方便的时候我接着问。完成后有劳务酬谢。

续聊（一句话，不重复自我介绍）：

王主任，接着上次的往下问，还有二十来分钟的量，您现在方便吗？

要点：

  • 先给"不用装"——这是转过来的原因，第一句就要回应；
  • 给出时长——医生据此决定现在答还是等会儿；
  • 给出回报——没有回报的对话会被当闲聊。

6. 题面脚本

题目与小程序版一致（同一套 32 题），按六个模块组织：

模块内容题号
A 患者画像看哪类、多少例、多重1–5
B 诊断检查初开什么、多久复查、可及性6–10
C 活动判断怎么算活动、怎么算难治11–15
D 治疗方案一线、进阶、联合、减量16–23
E 并发症长期用药的副作用管理24–28
F 随访依从频率、失访、教育29–32

完整逐题脚本见《路线 B · 话术脚本》。

每题的结构固定：编号 + 问题 + 一个例子，不超过 2 行。

示例：

1/32 您门诊的狼疮患者，以哪类为主？
     新发、复发，还是长期维持的？

2/32 一年大概看多少例？
     粗略量级就行

3/32 狼疮肾炎、神经精神狼疮这类重症，占多少？
     答不出可以填「不详」

规则：

  • 封闭题给选项（是/否、参与过/仅门诊），不要让医生自己组织语言；
  • 开放题强调"口语化就行"，否则医生会写长文或干脆不答；
  • 一次只发一题，医生答完再发下一题；
  • 医生答非所问时，复述问题 + 再给一个例子，最多两次。

7. 轮次与节奏

项规则
单题消息长度≤ 2 行
医生超时未答不催，等
中断后续接24 小时内可继续，从断点那道题接着问
一次聊多少10–11 题一轮，分三次；医生在第 12–15 题后开始敷衍
超过 24 小时记为「未完成」，次日追一次，仍无答复则关闭
一次性答完 32 题不推荐；医生硬要一次答完也允许，CC 按编号核对缺哪题

8. 完成判定与登记

这里有一个必须先讲清的设计取舍。

本期不做答案入库，所以答案是存在企微聊天记录里的。但完全不记录任何东西，会带来三个问题：发不出酬谢、算不出完成率、防不了重复。

因此：

记录什么记在哪说明
项目 / 医生 / 完成状态 / 完成日期 / 记录人后台最小登记只记状态，不记答案正文
答案原文企微聊天记录不复制、不导出、不入库

完成判定：

  • 完成：32 题都有可读的回答，允许 3 题以内记「不详」；
  • 部分完成：缺 4 题及以上，或某个模块整块缺失；缺的集中在哪个模块要标出来，这决定数据能不能用。

9. 酬谢发放

  • 依据：后台的「完成」登记，不看聊天内容；
  • 口径：与小程序线一致，不因渠道不同而打折；
  • 部分完成是否发放：本期不发，等第 14 节确认。

10. 异常与边界

场景处理
答非所问复述问题 + 换一个例子，最多 2 次；仍不懂 → 记为未答
只答了一半就消失24 小时内追一次；仍无 → 记「部分完成」
发语音请医生"麻烦打字给我，语音我没法记录"；医生坚持 → CC 自己转录成文字回填一句确认
发截图/照片同上，CC 转述成一句话，请医生确认
医生要求"别记录"说明：只用于本次调研，不存系统、不外传
医生中途要改答案直接发更正，以最后一条为准
医生问"这算完成了吗"答："我这边核对完就登记，酬谢按之前说的发"
同一医生被两个项目问分开问，一次只做一个项目，做完再约下一个
医生反过来推销/闲聊简短回应后拉回："那我们先把这个问卷过完"

11. 与小程序线的关系

11.1 分流判断

什么时候转 B 线，只有这三个入口，不做更多判断：

  1. CC 先发小程序卡片，走 A 线；
  2. 出现以下任一情况，转 B 线：
  • 医生明确说「不装 / 不会用小程序」；
  • 医生说「你直接问吧」；
  • 24 小时内三次未打开卡片；
  1. 转线动作：立刻把小程序侧该任务标「已转人工」，停止推送与催办；
  2. 转线后不再重复邀请，同一项目只走 B 线到底。

关键：分叉只有一次，发生在发卡片之后。不要一边等医生点卡片、一边在聊天里开始问——那等于两头催，医生会烦。

11.2 规则

项规则
关系并行，聊天版是兜底，不是替代
互斥同一人同一项目只走一条线
转线小程序 → 聊天：标「已转人工」；聊天 → 小程序：不推荐，会打断对话
完成后同步聊天版完成后，小程序侧该任务同步为「已完成（人工）」，避免系统继续催
数据合并两条线的完成状态在后台合并统计，答案不合并（聊天版没有结构化的答案）

12. 指标

指标说明目标
转人工率发过卡片但转聊天版的比例观察值，不设目标
聊天版完成率开始对话的医生中答满 32 题的比例≥ 70%
平均轮次从开场到最后一题的消息轮数约 70 轮（分 3 次）
CC 单份工时一个医生从开场到登记完成的累计耗时25–30 分钟
覆盖率提升相比只有小程序线时的总完成数提升 ≥ 15%

13. 分期

期范围
P0开场话术、32 题对话脚本与分批策略、后台最小登记（项目/医生/状态/日期）、酬谢发放
P1登记页做成列表，支持筛选与导出；断点续接提醒
P2（本期不做）会话存档接入、答案自动解析、自动完整性判断

14. 待确认

  1. 部分完成给不给酬谢——不给可能伤感情，给了又会让"答一半"变成策略；
  2. 登记落在哪——现有后台新建一个轻量列表，还是先在企业微信的客户备注里过渡；
  3. 是否按项目默认分流——比如某个项目一律走聊天版，不用先发卡片；
  4. 题库是否与小程序版完全一致——聊天版题目要更短，可能需要一套精简版题面；
  5. CC 的产能上限——一个 CC 一天能问几份，决定这条路线的实际覆盖能力。
